# Implementation Validation Checklist

Comprehensive checklist for validating implementation work in the YASK system.

## Pre-Implementation Setup
- [ ] **Document Accessibility**: All spec documents (requirements.md, design.md, tasks.md) exist and are validated
- [ ] **Task Selection**: Specific task selected from tasks.md for implementation
- [ ] **Context Loading**: All relevant context loaded before implementation begins
- [ ] **Environment Setup**: Development environment properly configured
- [ ] **Resource Assessment**: Required tools and dependencies identified

## Usage Instructions

1. **Pre-Implementation**: Ensure all spec documents are validated and task is selected
2. **Context Loading**: Load all relevant context before beginning implementation
3. **Focused Execution**: Maintain single task focus throughout implementation
4. **Quality Assurance**: Apply quality assurance measures throughout implementation
5. **Verification**: Verify functionality and quality at each step
6. **Documentation**: Document implementation thoroughly
7. **Completion Verification**: Verify true completion before claiming completion
8. **User Communication**: Communicate progress and results clearly to user
9. **Final Validation**: Apply final validation checklist before completion
10. **Approval**: Obtain user approval before final completion

## Common Issues and Solutions

### Context Issues
- **Issue**: Insufficient context loading
- **Solution**: Ensure all spec documents are read and understood
- **Example**: Read requirements.md, design.md, and tasks.md before implementation

### Focus Issues
- **Issue**: Implementation scope creep
- **Solution**: Maintain strict focus on selected task
- **Example**: Only implement the specific task selected by user

### Quality Issues
- **Issue**: Code quality below standards
- **Solution**: Apply coding standards and review code
- **Example**: Follow project naming conventions and add proper documentation

### Completion Issues
- **Issue**: False completion claims
- **Solution**: Verify actual completion before claiming completion
- **Example**: Test functionality thoroughly before claiming task complete

### Documentation Issues
- **Issue**: Insufficient implementation documentation
- **Solution**: Provide comprehensive summary of implementation
- **Example**: Document approach, decisions, changes, and verification results
